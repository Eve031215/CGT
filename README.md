# 数据文件说明（README）

## 1. 文件概览

本项目包含三类文件：数据文件、数据清洗与编码程序，以及用于模型盲选/盲评的网页。

| 文件名 | 内容 | 有效数据行数 | 说明 |
|---|---|---:|---|
| `final data part1.xlsx` | 最终编码数据（第 1 部分） | 189,149 | `content_id` 范围为 0–243,501；编号不连续是因为清洗后部分原始记录未进入最终数据。 |
| `final data part2.xlsx` | 最终编码数据（第 2 部分） | 189,148 | 接续第 1 部分，`content_id` 范围为 243,502–557,630。 |
| `Artificial Open Coding.xlsx` | 双人编码及人工整合的开放编码材料 | 911 | 用于展示或支持人工开放编码、协商整合与代码形成过程，不是最终全量分析数据。 |
| `CLEAN CODE` | 数据清洗代码 | — | 对原始社交媒体帖子执行标准化、记录排除、重复文本和模板噪音处理，生成进入后续编码的清洗语料。 |
| `stage123_all_in_one.py` | 三阶段编码程序 | — | 将三个连续编码阶段整合在一个 Python 脚本中，用于从清洗语料生成并逐步整理编码结果。 |
| `index.html` | 模型盲选/盲评网页 | — | 在隐藏模型身份的情况下展示候选模型结果，供评审者比较、选择或评分。 |

`final data part1.xlsx` 与 `final data part2.xlsx` 的列结构完全一致。将 part2 追加到 part1 下方后，共有 **378,297 条记录**，且 `content_id` 均不重复。合并时只保留一次表头，不要重新生成或重排 `content_id`。

## 2. 项目文件关系与处理顺序

各文件在研究流程中的关系如下：

1. 使用 `CLEAN CODE` 对原始帖子进行清洗，得到可进入编码阶段的语料。
2. `Artificial Open Coding.xlsx` 提供人工开放编码及整合结果，可作为模型比较、编码参照或方法展示材料。
3. 使用 `index.html` 对不同候选模型的编码结果进行匿名展示和盲选/盲评，减少模型名称对评审判断的影响。
4. 确定使用的模型或编码方案后，通过 `stage123_all_in_one.py` 连续执行三个编码阶段。
5. 最终记录整理并拆分保存为 `final data part1.xlsx` 和 `final data part2.xlsx`。

简化后的处理链为：

> 原始帖子 → `CLEAN CODE` → 清洗语料 → 模型盲选/盲评 → `stage123_all_in_one.py` → `final data part1.xlsx` + `final data part2.xlsx`

## 3. 数据文件之间的关系

`Artificial Open Coding.xlsx` 记录人工编码者对样本文本的初始判断及协商后的开放编码结果；两份 `final data` 则保存全量语料经过各层编码后的最终数据。

最终数据中的编码层级可按下列顺序理解：

> `原文(OT)` → `一级编码` → `二级编码` → `旧的-轴心编码ID` / `三级编码` → `心理需求命名` / `ID` / `EN`

- `一级编码`：贴近单条文本内容的细粒度开放编码。本数据中共有 51,136 种不同表述。
- `二级编码`：由开放编码进一步归并形成的主轴编码，共 106 类。
- `三级编码`：进一步归纳形成的 10 个轴心编码，使用较完整的理论性名称。
- `心理需求命名`、`ID` 和 `EN`：对上述 10 个轴心编码进行最终命名和重新编号后的中文简称、最终编号及英文名称。

## 4. `final data part1.xlsx` 与 `final data part2.xlsx` 列名说明

两份文件均只有一个工作表（`Sheet1`），包含以下 11 列。

| 列名 | 数据类型/形式 | 含义 |
|---|---|---|
| `content_id` | 整数 | 记录在原始数据中的唯一编号。该编号在两个文件合并后仍唯一，但因数据清洗存在跳号，不应将其理解为最终文件中的连续行号。 |
| `created_at` | 文本时间，格式通常为 `YYYY-MM-DD HH:MM:SS` | 帖子的发布时间。当前 Excel 中以文本形式保存。 |

| `原文(OT)` | 文本 | 进入编码与分析的帖子文本；`OT` 表示 Original Text。数据中有 1 条为空（`content_id = 198897`）。 |
| `一级编码` | 文本 | 针对单条帖子生成的细粒度开放编码，概括该文本中具体表达的互动目的或心理诉求。 |

## 6. `Artificial Open Coding.xlsx` 列名说明

该文件只有一个工作表（`Sheet1`）。前五列为有效字段，第六列没有表头，不属于正式数据结构。

| 列名 | 含义 |
|---|---|
| `句子` | 提供给人工编码者进行开放编码的原始文本或帖子句子。 |
| `编码者1_编码列表` | 编码者 1 独立给出的一个或多个初始开放编码。内容以类似 Python 列表的文本形式保存，例如 `['编码A', '编码B']`。 |
| `编码者2_编码列表` | 编码者 2 独立给出的一个或多个初始开放编码。`/` 表示该编码者未给出有效编码或该项未编码。 |
| `人工整合开放编码` | 对两位编码者结果进行比较、讨论或人工判断后形成的整合开放编码，是该文件中应优先使用的人工共识结果。 |
| `备注` | 对整合编码的证据、判断依据或语义解释。共有 6 条为空。 |
| 无表头第六列 | 非正式字段。仅 Excel 第 376 行存在一个值，内容与该行编码信息重复，建议在分析时忽略整列。 |

该工作表的 Excel 第 913–927 行为空白行，不计入 911 条有效记录。读取数据时应删除全空行。

## 7. 程序文件说明

### 7.1 `CLEAN CODE`

该文件是数据预处理程序，负责将原始社交媒体帖子转换为可用于编码的清洗语料。其主要作用包括：

- 对帖子文本进行标准化，例如处理提及、链接、话题符号、方括号表情、异常字符和多余空白；
- 排除转发、回复链、无有效中文内容、过短或仅由标点等组成的无效记录；
- 识别重复文本、推广模板、互动模板及其他批量噪音；
- 保留原始记录标识，便于从清洗结果追溯到原始帖子；
- 输出清洗后的数据及相应的清洗统计或审计信息。

`CLEAN CODE` 是仓库中显示的文件名。若实际下载后带有 `.py` 等扩展名，应以下载后的真实文件名运行。具体输入路径、输出路径和运行依赖以代码中的配置为准。

### 7.2 `stage123_all_in_one.py`

该文件是整合式三阶段编码脚本，用于在同一程序中依次完成三个连续的编码处理阶段。其总体作用是：

- 读取已经清洗的帖子文本；
- 执行第一阶段编码并形成初始编码结果；
- 将前一阶段结果传递给第二阶段进行复核、归并或提升；
- 在第三阶段进一步统一和整理编码表述，形成可用于后续人工归纳或最终数据整理的结果；
- 保存各阶段结果或最终编码结果，便于检查中间过程与失败记录。

该脚本的 API 配置、模型名称、输入输出路径、批次设置和断点续跑方式应以脚本中的实际参数为准。运行前应先完成数据清洗，不应直接把未经清洗的原始数据作为正式输入。

### 7.3 `index.html`

该文件是用于模型盲选/盲评的本地网页界面。其主要用途是：

- 隐藏候选结果对应的模型名称或固定身份信息；
- 并列或依次展示不同模型对同一材料的编码结果；
- 供评审者根据统一标准进行比较、选择或评分；
- 减少模型品牌、名称或先验印象对判断造成的影响；
- 为模型选择和后续全量编码提供评审依据。

通常可在浏览器中打开 `index.html`。如果网页依赖同目录中的数据文件、脚本或样式文件，应保持原有目录结构；具体数据导入、评分保存和结果导出方式以网页中的实际按钮和提示为准。

## 8. 推荐读取与合并方式

1. 分别读取 `final data part1.xlsx` 和 `final data part2.xlsx` 的 `Sheet1`。
2. 检查两份文件的 11 个列名及顺序完全一致。
3. 按行追加 part2，不要按 `content_id` 范围补齐缺失编号，也不要重新编号。
4. 合并后应得到 378,297 条记录和 378,297 个唯一 `content_id`。
5. 分析最终心理需求类别时使用 `ID`、`心理需求命名` 和 `EN`；若要复现旧版轴心编码，则使用 `旧的-轴心编码ID` 与 `三级编码`。
6. 读取 `Artificial Open Coding.xlsx` 时保留前五列，删除全空行，并忽略无表头的第六列。

## 9. 数据使用注意事项

- `content_id` 是标识符，不是连续数值变量；统计分析时不应计算其均值或大小关系。
- `created_at` 当前为文本，如需按时间分析，应先显式转换为日期时间类型。
- `ip_location` 含缺失值，且表示平台展示的 IP 属地，不等同于用户的精确常住地或实际位置。
- `一级编码` 的表述较细且数量较多，适合追溯具体语义；汇总统计通常应使用 `二级编码` 或最终心理需求字段。
- `旧的-轴心编码ID` 与最终 `ID` 不能仅凭编号连接，必须使用本 README 中的映射关系或同时参考相邻的名称列。
- 两份 final data 是一个数据集的物理拆分，不应被当作两个独立样本分别解释。
